Factory diorama reproduction

The four reproduction helpers originally developed in eab1a34 are reconciled with the current authored scene, cargo bridge, enrichment and ramp guardrail mounts. Camera, phase nodes, paths and the published runtime image/metadata pair remain the approved reference.

The runtime measurement uses getAtlasCamera, atlasActorScale and atlasActorBounds from the current World atlas. The tracked report binds the runtime sources and published metadata with SHA-256 over UTF-8 text normalized to LF, so an ordinary Windows/Linux checkout does not invalidate a proof. Ten fixed viewport/HUD scenarios cover five stage selections in island and terrain panorama modes. These are deterministic model inputs; no fresh browser HUD measurement or universal interpolation bound is claimed.

Physical body clearance and raster overdraw have separate meanings. The camera-independent 16×26 body comes from atlasActorBounds. Rounded CSS pixels come from the actual actor painter and can cover more world space when zoomed far out. The Blender report retains both sets of contacts: physical equipment contacts fail the audit; panorama pixel-envelope contacts remain explicit visual diagnostics. A full transparent grid rectangle is conservative and does not establish an opaque-pixel collision. Ground support, headroom, shadow and ramp mounts remain separate checks.

Reproduction commands, from the repository root:

1. Regenerate the runtime envelopes, or check the committed report without rewriting it:

   node --import tsx tools/diorama/measure_fabrica_envelopes.ts
   node --import tsx tools/diorama/measure_fabrica_envelopes.ts --check

2. Build and audit the scene without rendering. Blender must exit on Python failure:

   blender -b -t 8 --python-exit-code 1 -P tools/diorama/render_fabrica_map.py -- --scene-only --output-dir .cache/diorama/fabrica
   blender -b .cache/diorama/fabrica/fabrica-map-prototype.blend --python-exit-code 1 -P tools/diorama/check_factory_guardrail_mounts.py -- --output-dir .cache/diorama/fabrica/audit

3. Render the source-matched cache into a separate directory. This checks the cache file hash and current source hashes, repeats clearance checks and renders the full 1920×1200 image at 192 samples. A historical or modified cache is rejected:

   blender -b .cache/diorama/fabrica/fabrica-map-prototype.blend -t 8 --python-exit-code 1 -P tools/diorama/render_fabrica_cached.py -- --output-dir .cache/diorama/fabrica-cached

   Alternatively, build, audit and render directly from fresh source:

   blender -b -t 8 --python-exit-code 1 -P tools/diorama/render_fabrica_map.py -- --final --output-dir .cache/diorama/fabrica-final

4. Package and review the candidate. Python with Pillow is required:

   python tools/diorama/package_fabrica_map.py --input-dir .cache/diorama/fabrica-cached
   python tools/diorama/review_fabrica_map.py --input-dir .cache/diorama/fabrica-cached
   python tools/diorama/test_fabrica_tools.py

The renderer stages exports under export/, audits under audit/, the Blender scene and its source-provenance sidecar under the chosen output directory. The source-only boundary used by the Porto/Factory and Factory/Serra generators is preserved.

Packaging requires a current render/provenance pair, approved camera/nodes/routes, passing physical audits, an unclipped alpha frame within one pixel of the published bounds and a payload of at most 350 KB. It uses WebP quality 91/method 6 and preserves the published metadata bytes. Its manifest records fresh audit summaries separately from the published historical metadata summaries.

Packaging writes to a candidate directory by default. After visual review, --install-assets explicitly installs only the candidate WebP, atomically, after checking that the published pair has not changed. The candidate manifest and route-overlay image remain review evidence; the existing runtime image is not regenerated by this integration.

The original pre-atlas reports remain accessible in commit eab1a34. Current verification evidence is recorded in fabrica-reconciliation-verification.json; current support and billboard audit outputs are generated from source into the staged directory.
